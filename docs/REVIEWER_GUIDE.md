# MindMend Guardian Reviewer Guide

Use this guide if you are reviewing MindMend Guardian as a recruiter, sponsor, partner, nonprofit supporter, or technical evaluator.

## What This Project Shows

MindMend Guardian demonstrates privacy-first youth and family safety product thinking:

- local-first sensitive-data architecture direction
- risk-signal workflow design
- supportive response framing
- human-in-the-loop escalation boundaries
- privacy and safety documentation discipline
- nonprofit mission alignment

## Best First Read

1. `README.md` — project overview and mission
2. `docs/STATUS.md` — current working status and non-claims
3. `docs/THREAT_MODEL.md` — youth/family safety risks and trust boundaries
4. `docs/PRIVACY_AND_SAFETY.md` — deployment and safety notes
5. `SECURITY.md` — responsible disclosure and vulnerability scope

## What To Run

```bash
python -m pip install --upgrade pip
pip install pytest
pytest
```

## What To Look For

- Does the project clearly protect sensitive family data?
- Are safety limits and crisis boundaries visible?
- Does it avoid pretending to be a therapist or crisis service?
- Are prototype claims tied to docs, tests, and code?
- Is the roadmap realistic for local-first hardening?

## Current Evaluation

MindMend Guardian should be evaluated as a mission-aligned prototype and portfolio signal. It is not a clinical, emergency, or compliance-certified system. Its value is in the architecture, responsible framing, and local-first youth safety direction.
